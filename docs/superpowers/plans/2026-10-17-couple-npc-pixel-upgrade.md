# 情侣 NPC 像素升级实施计划

**目标：** 让情侣在游戏正常画面大小下就能认出：女生有刘海、微微胖的可爱体形和裙子；男生是黄毛体育生。

**做法：** 分别制作两套 24×24 像素角色图，给情侣使用独立绘制方式。保留目前的出场、行走、投喂、拥抱和接吻规则，不改变其他角色。

**设计依据：** [情侣 NPC 像素升级设计](../specs/2026-10-17-couple-npc-pixel-design.md)

## 涉及文件

- 新建 `src/data/couple-sprites.js`：保存两人的颜色和各方向像素图。
- 新建 `src/npc/couple-render.js`：根据朝向、行走和亲昵动作选择并绘制图像。
- 修改 `src/npc/index.js`：仅把情侣交给新的绘制函数，其他 NPC 继续使用原有绘制方式。
- 修改 `src/npc/couple.js`：把当前是拥抱还是接吻传给绘制函数，动作结束后清除。
- 新建 `deploy/tests/couple-sprites.test.js`：检查图片尺寸、颜色和动作帧选择。
- 扩充 `deploy/tests/npcs.test.js`：检查拥抱、接吻状态与原有行为。

## 任务一：制作两人的像素图

- [ ] 先写检查：每人都要有正面、背面、侧面待机与行走帧，以及拥抱和接吻帧；每帧严格为 24 行、每行 24 像素；使用的颜色必须在该角色的调色板中。
- [ ] 运行 `node --test deploy/tests/couple-sprites.test.js`，确认新增检查会因缺少像素图而失败。
- [ ] 绘制女生：正面和侧面能看见刘海；脸颊、手臂和身体轮廓略圆润；裙摆和腿之间有清楚的间隙。背面也保留发型和裙装特征。
- [ ] 绘制男生：黄色短发在正面、侧面和背面都清楚；肩部和动作体现体育生的活力。衣服颜色仅作辅助。
- [ ] 给拥抱和接吻分别绘制头部、手臂位置不同的姿态。运行像素图检查，通过后提交这一阶段的文件。

## 任务二：接入游戏绘制

- [ ] 先写检查：情侣两人使用不同的图；向左时侧面图镜像；走路时按现有节奏切换两帧；拥抱和接吻时优先显示对应动作图。
- [ ] 运行新检查，确认它因缺少绘制函数而失败。
- [ ] 实现情侣专用绘制：按原角色的位置对齐脚部；实际绘制大小为地图中的 24×24 像素；关闭平滑处理，保持像素边缘清楚；缓存已生成的图像，避免每一帧重复制作。
- [ ] 在 NPC 绘制入口只为情侣启用新函数。运行 `node --test deploy/tests/couple-sprites.test.js deploy/tests/npcs.test.js`，确认情侣和其他 NPC 的相关检查通过，然后提交这一阶段的文件。

## 任务三：检查亲昵动作和实际画面

- [ ] 给现有测试增加检查：开始拥抱或接吻时，两人都获得正确的动作状态；结束后清除状态。先运行测试，确认新检查能发现尚未接入的状态。
- [ ] 在情侣行为代码中传递和清除动作状态。保留现有的出现概率、路线、动作时间、爱心频率和投喂规则。
- [ ] 运行 `npm test`，确认所有测试通过。
- [ ] 在电脑和手机尺寸的前庭画面中，分别检查行走、拥抱、接吻：正常大小下能看清刘海、裙子、圆润体形和黄发；脚部位置稳定；两种亲昵姿态不同；爱心位于两人之间；与玩家和猫的前后遮挡正常。
- [ ] 如果亲昵时身体遮住了关键特征，仅调整情侣姿态图或必要的站位，并同步更新相关测试。复查画面后提交这一阶段的文件。

## 完成标准

1. 不放大游戏画面，也能认出女生的刘海、裙子和略圆润的轮廓，以及男生的黄发。
2. 拥抱与接吻看上去是两种不同动作，原有爱心和时间规则正常。
3. 全部测试通过，电脑与手机画面没有脚部错位、明显遮挡或其他角色外观变化。
