## 1. 概述

给已完成的像素图书馆游戏加入声音：**事件音效**（投喂、猫叫、满心跟随、打盹）+ **卡农 BGM**（图书馆室内循环）。

采用**程序化 Web Audio 合成**路线——不引入任何音频文件，所有声音由代码实时生成。

## 2. 决策记录

| 决策点 | 结论 | 理由 |
|---|---|---|
| 范围 | 事件音效 + 卡农 BGM | 室外场景与第二首 BGM 属于新 feature，以后单独计划 |
| 音源方案 | 程序化合成（Web Audio API） | 零素材零文件、`file://` 完美兼容；能做每猫专属嗓音与 BGM 变奏，素材方案做不到 |
| BGM 曲目 | 卡农（Pachelbel, ~1680，公有领域） | 循环变奏曲式天然适合 BGM；旋律公版可直接演奏 |
| ❌ 不采用 | Bandari《Annie's Wonderland》 | 1990 年代现代作品，旋律受版权保护，不可使用（已向用户说明并确认） |
| 每猫嗓音 | 10 只猫各有专属基频（400–800Hz） | 呼应"每只猫有名字和性格"的设定，听声辨猫 |
| 静音控制 | M 键切换（不做音量滑块） | YAGNI；静音已满足"想安静玩"的需求 |
| 音频文件 | 无（零素材） | 保持"双击即玩、零依赖、零构建"的项目哲学 |
| BGM 变奏机制 | ❌ 不做（固定循环） | 用户明示只要"温和的氛围"；变奏是为"不腻"加的花样，实现复杂度不划算——真觉得腻了再加，扩展点留着 |
| 脚步 / 环境音 | ❌ 不做 | 节奏性"嗒嗒"声会打破图书馆的安静感，与"温和"相冲 |

## 3. 声音设计

### 3.1 事件音效清单

| 事件 | 挂钩位置（main.js 当前版本） | 合成设计 |
|---|---|---|
| 投喂放碟 | `feed()` 返回 true（L107） | 三角波 180→120Hz 下滑，60ms 衰减，音量 0.20 |
| 猫吃完叫 | hearts +1（L122，现冒"喵♪"文字处） | 该猫专属基频，音高包络 ×1.0→×1.5→×0.8，约 180ms，6Hz 颤音（±3%），音量 0.25 |
| 满心跟随 | `eat`→`follow`（L126） | 三音符上行 D5→F#5→A5（各 150ms），三角波 + 稍长衰减，音量 0.22 |
| 猫咪打盹 | 每次进入 `nap` 的边沿（用 main.js 现有的 `beforeState` 对比检测） | ~55Hz 锯齿波过低通，2s 渐弱，音量 0.06（"呼噜"感，极轻） |
| BGM | 首次按键后自动启动 | 见 3.3 |
| 静音切换 | M 键 | 无声，HUD 显示 🔊/🔇 |

### 3.3 卡农 BGM 设计

- **调性**：D 大调
- **和弦进行**：D → A → Bm → F#m → G → D → G → A（每和弦 2 秒，一轮 16 秒循环）
- **三层织体**：
  1. **低音层**：和弦根音长音（低八度，音量 0.10，时值 2s）
  2. **琶音层**：和弦内音分解流动（八分音符，音量 0.14）
  3. **旋律层**：卡农主题原旋律（公有领域，音量 0.16）
- **音色**：三角波 + 低通滤波（2500Hz）+ ADSR（attack 0.008s / decay 1.4s / sustain 0 / release 0.3s）+ 延迟回声（DelayNode 0.28s，反馈 0.25，wet 0.3）→ 音乐盒/八音盒质感
- **固定循环**：每轮结构完全一致（`canonBar()` 为确定性函数），一轮 = 三层音符事件的时间轴
- **温和调校原则**：整体音量低（BGM 总线 0.18）、只用柔和波形（三角/正弦）、起音快衰减长（像八音盒的余韵）、不放强节奏——目标是"像远处角落的八音盒在慢慢转"
- **扩展点**：如日后觉得循环单调，可在 `canonBar()` 里按轮次参数做变奏（八度位移 / 装饰音 / 呼吸轮），接口不变
- **音量**：BGM 总线 0.18（低于音效）

### 3.4 音量与静音

- 主增益 `masterGain` 默认 0.9；静音时置 0（音效与 BGM 一起）
- 静音状态由纯逻辑状态机维护（`isMuted()` / `toggleMute()`），HUD 的 `#sound` span 显示 🔊 / 🔇

## 4. 技术设计

### 4.1 文件与接口

新增 `js/audio.js`（第 5 个 JS 文件，全局 `Sound` + 末尾 CJS 兼容导出）。脚本加载顺序变为：

```
sprites.js → map.js → cats.js → audio.js → main.js
```

```js
Sound.init()                    // 懒初始化：首次按键时创建 AudioContext（浏览器要求用户手势）
Sound.play(name, opts)          // 音效：'dish' | 'meow' | 'follow' | 'purr'
                                //   opts：'meow' 必须传 { cat }（按 cat.id 取专属嗓音）；其余可省
Sound.startBgm() / stopBgm()    // 卡农循环启停
Sound.toggleMute() / isMuted()  // 静音状态机
```

main.js 挂钩点：L107（dish）、L122（meow）、L126（follow）、nap 边沿（purr）、首次 keydown（init + startBgm）、M 键（toggleMute + HUD）。

### 4.2 合成实现要点

- **一次性振荡器**：每个音效 = `createOscillator` + `createGain`（包络）→ 播完 `stop()`，节点由 GC 回收（增益归 0.0001，近似静音），不会累积可感知的泄漏
- **前瞻调度器**（lookahead scheduler）：`setInterval` 25ms 检查一次，把未来 100ms 内该响的音符用 `ctx.currentTime + offset` 排入音频时间轴——节奏精确性靠音频时钟而非定时器，不会抖
- **顶层零 DOM/零音频 API**：`AudioContext` 仅在 `init()` 内部创建 → `js/audio.js` 在 Node 中可直接 `require` 测试纯逻辑
- **`canonBar()` 完全确定性**：无随机数，一轮音符事件的时间轴固定（砍掉变奏后的额外收益——测试无需注入随机源）

### 4.3 测试与验证

1. **单测**（`tests/audio.test.js`，node:test）：
   - `noteFreq`：A4 = 440、C5 ≈ 523.25、F#5 ≈ 739.99
   - `CAT_VOICES`：10 只猫齐全、基频互不相同、均在 400–800Hz
   - `CANON_PROGRESSION`：8 个和弦、和弦音正确（D/F#m/Bm 等三和弦构成）
   - `canonBar()`：一轮包含三层音符事件（低音 8 个 / 琶音 64 个 / 旋律 ≥16 个）、时间跨度 16s、所有音符频率为正且在合理音域、结果确定性（两次调用结果相同）
   - 静音状态机：toggle 反转、静音状态下 `play()` 不产生输出
2. **Playwright**：首次按键后 AudioContext 创建成功（`page.evaluate` 读音频图）；静音时主增益为 0、非静音 > 0；BGM 启动后音频节点随时间增长
3. **人工试听**（最终验收）：好不好听只能人判断——由用户亲自听并反馈
